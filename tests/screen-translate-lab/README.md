# Screen Translate Lab

Manual acceptance tooling for the screen translate pipeline. It shows every case
side by side in the browser: source, raw detector output, locator boxes at
adjustable thresholds, and a production preview rendered by the real application.

The tooling lives here. Case inputs and run artifacts stay outside the
repository so real-run artifacts are never tracked.

## Run

```
python tests/screen-translate-lab/viewer-server.py
```

The server listens on `http://127.0.0.1:8765/viewer.html` and opens a browser.

## Layout

Tracked here:

| File | Purpose |
| --- | --- |
| `viewer.html` | Case grid, threshold controls, comments, preview triggers |
| `viewer-server.py` | Static host plus the `/api/*` endpoints the viewer calls |
| `lab_paths.py` | Resolves the artifact root shared by every script |
| `locator-lab.py` | Runs the detector locator and recognizer at chosen thresholds |
| `run-detector-raw.py` | Runs the worker over every case and regenerates `viewer-data.js` |
| `production-preview.py` | Drives the built application through its lab queue |
| `run-production-previews.py` | Runs the production preview for every case and summarizes it |

Artifacts, under `%LOCALAPPDATA%\SGT-Development\manual-tests\screen-translate`
unless `SGT_SCREEN_TRANSLATE_LAB_ROOT` overrides it:

```
inputs/case-NN/
  source.jpg                   selection the case replays
  detector-raw.{json,jpg}      worker output and its overlay
  detector-raw-numbered.jpg    overlay with region ids
  detector-run.json            run record for the case
  locator-probability.npz      cached locator probability map
  comments.json                review notes written from the viewer
  production-preview/          rendered previews
viewer-data.js                 generated by run-detector-raw.py
archived-runs/, *-result.json  historical sweeps
```

## Full run

Add a case by dropping `source.jpg` into a new `inputs/case-NN`, then:

```
python tests/screen-translate-lab/run-detector-raw.py
python tests/screen-translate-lab/run-production-previews.py
```

The first regenerates every case's detector artifacts and `viewer-data.js`. The
second translates every case end to end. Pass case names to run a subset, which
merges into the existing summary instead of replacing it, and pace the calls when
a provider is rate limited:

```
python tests/screen-translate-lab/run-production-previews.py case-10 case-15 --attempts 3 --pace 90
```

Translation runs against live providers, so free-tier request and daily token
limits are the usual cause of a failed case. The summary records the provider
error verbatim for each one.

## Production preview

`production-preview.py` launches the debug build from the managed dev cache with
`--screen-translate-lab-queue`, writes `request.json`, and waits for the run
evidence. It therefore needs a debug build present at
`%LOCALAPPDATA%\SGT-Development\cache\cargo\dev\debug\screen-goated-toolbox.exe`,
an interactive desktop session, and `SGT_SCREEN_TRANSLATE_AUTO_EVIDENCE=1` for
evidence capture. It is a manual acceptance tool, not a CI gate.
