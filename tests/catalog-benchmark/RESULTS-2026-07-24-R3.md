# Catalog Benchmark Results — 2026-07-24 R3

> Historical record only. The three-run rolling policy described below was
> retired on 2026-07-26. Current decisions use
> `RESULTS-2026-07-26-PROTOCOL6.md` and the latest-complete-run policy.

This record supersedes the R2 vision timings and image-to-text catalog
decisions. R2 used an older streaming benchmark path. R3 uses benchmark
protocol 5 and the same non-streaming, plain-text production path as the
built-in `Extract text` preset.

## Method

- Ten OCR cases per endpoint, in increasing difficulty.
- Three independent runs per endpoint; failed requests remain availability
  evidence.
- Accuracy and reliability use all 30 attempts.
- User-facing latency is the median of the three per-run medians for the five
  successful OCR inputs whose effective longest edge is at most 1024 px.
- Representative and all-case P95 values retain normal-crop and stress-tail
  evidence respectively.
- Every request records the effective endpoint-owned reasoning and vision
  request profile.

`*` marks sparse quality evidence. Three independent runs now contain an
admitted representative call, so the 1.931-second latency is catalog-ready.
The rolling window still returned 27 TPD quota errors, so Qwen remains the last
fallback even though its three admitted small-image calls were accurate.

The Cerebras row explains the real-app impression that prompted this rerun.
Several ordinary small-crop calls completed in 0.58–1.95 seconds, but high-load
calls produced long queue tails and two 429 responses. The median therefore
keeps Cerebras ahead of both Google-hosted Gemmas without hiding its poorer
tail consistency.

## Fast request policy learned

| Endpoint group | Production request policy |
| --- | --- |
| Gemini Flash-Lite / Google | Text first, provider-default media resolution, minimal reasoning, non-streaming plain-text OCR |
| Gemma / Google | Image first, provider-default media resolution, minimal reasoning, non-streaming plain-text OCR |
| Gemma / Cerebras | Text first, provider-default image handling, reasoning effort `none`, non-streaming plain-text OCR |
| Qwen / Groq | Text first, reasoning `none` with hidden reasoning output, endpoint-recommended non-thinking sampling, and a catalog-owned 512-token completion ceiling |

The endpoint profile is catalog-owned and shared by Windows, Android, the live
benchmark, and quota preflight. OCR does not request JSON unless a caller
supplies an actual response schema.

## Competing explanations tested

- Google Gemma's long tails survived text-first versus image-first input,
  provider-default versus low/medium/high media resolution, streaming versus
  non-streaming delivery, and a compact prompt. Forced lower resolution reduced
  billed image tokens but did not produce a durable latency win.
- Gemini Flash-Lite did not gain repeatable completion speed from a forced
  media resolution. Minimal-thinking calls reported zero thought tokens in the
  probe, so further reasoning reduction was not available.
- Non-streaming OCR buffers the response, so recorded TTFO and full-answer time
  are nearly identical. This is the correct product-visible latency for
  `Extract text`; an apparent post-first-output burst is delivery behavior, not
  inference throughput.
- Qwen's former 2,048-token completion reservation inflated Groq admission from
  roughly 2,937 to 4,483 requested tokens for the same small OCR input. A
  512-token ceiling returned the complete 220-token probe answer while reducing
  quota pressure. Live probing also showed that the endpoint rejects `top_k`
  and `min_p`, so production omits them.
- Groq sometimes returned a short structural `retry-after` header even when the
  error body reported a 16–20 minute TPD wait. Retrying that response made
  quota-exhausted calls take 28–51 seconds. Windows and Android now retry only
  a delay of at most two seconds; longer windows fail immediately into normal
  fallback/cooldown behavior. A production-binary live check against the
  exhausted window returned the preserved 429 in 0.88 seconds after this
  change. The benchmark deliberately bypasses chain cooldown and kept hitting
  the exhausted endpoint; several later first 429 responses still took
  12–19 seconds inside Groq. Normal product execution cools the model for five
  minutes after the first quota error, so it does not repeatedly pay those
  provider-side tails.

## Catalog decisions

- Default image-to-text endpoint: Gemini 3.1 Flash-Lite.
- General image-to-text retry order: Gemini 3.1 Flash-Lite, Gemini 3.5
  Flash-Lite, Cerebras Gemma 4 31B, Google Gemma 4 31B, Google Gemma 4 26B A4B,
  then Qwen 3.6 27B.
- Help Assistant and Computer/Phone Control keep their correctness-sensitive
  Gemini 3.5 Flash-Lite → Gemini 3.1 Flash-Lite chain.
- Speed labels use the three-run small-image value. Large-image and provider
  overload tails remain in the benchmark record rather than distorting normal
  crop latency.
